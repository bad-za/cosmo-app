# План: Космический монорепозиторий (Пульсар-часы + Орбитальный симулятор)

Этот документ — спецификация для Claude Code. Реализуй проект поэтапно, строго в указанном порядке. Не переходи к следующему этапу, пока не выполнены критерии приёмки текущего.

## Контекст о пользователе (важно)

- Пользователь НЕ читает код и не имеет опыта с Three.js и фронтендом. Не проси его делать код-ревью.
- Роль пользователя — визуальная приёмка. После каждого этапа выдавай короткую инструкцию: какую команду запустить и что он должен увидеть/услышать, чтобы считать этап успешным.
- Вся уверенность в корректности кода — через автотесты и твою самопроверку, не через ревью пользователя.

## Принципы работы агента

1. Малые итерации: один этап = один работающий, запускаемый результат.
2. Физическое ядро покрывается тестами обязательно (детали в этапах). Тесты гоняй сам после каждого изменения ядра.
3. Перед коммитом каждого этапа: проект собирается без ошибок, тесты зелёные, `npm run dev` поднимает рабочее приложение.
4. Если внешний API недоступен — используй захардкоженный fallback (указан в этапах), не блокируй разработку.
5. Пиши простой, читаемый код без преждевременных абстракций. Комментарии — на русском.

## Стек и ограничения

- TypeScript, Vite, Three.js, Web Audio API.
- Монорепозиторий на npm workspaces (или pnpm, если установлен).
- КРИТИЧНОЕ ограничение: пакеты `core` и `render` не должны зависеть от Node.js API и от специфики браузерного окружения сверх необходимого. Причина: в будущем приложение упаковывается в Tauri (десктоп/Steam) и Capacitor (iOS/Android). Любая логика — платформонезависимая; платформенные вещи только в `apps/*`.
- Никаких тяжёлых физических библиотек: гравитация и интеграторы пишутся руками, это ядро проекта.

## Структура репозитория

```
space/
  CLAUDE.md              # соглашения проекта (создать на этапе 0)
  package.json           # workspaces
  packages/
    core/                # физика и астрономия: чистый TS, ноль зависимостей
      src/nbody/         # гравитация, интеграторы
      src/pulsar/        # расчёт фазы пульсаров
      src/units.ts       # система единиц
      tests/
    render/              # общие Three.js-компоненты: сцена, камера, тела, следы орбит
    data/                # скрипты загрузки данных + закэшированные JSON
  apps/
    pulsar-clock/        # приложение 1
    simulator/           # приложение 2
    dashboard/           # этап склейки (создаётся последним)
```

## Система единиц (зафиксировать в core/src/units.ts)

- Расстояние: астрономические единицы (а.е.)
- Время: годы (в UI конвертировать в удобное)
- Масса: массы Солнца
- Гравитационная постоянная в этих единицах: G = 4π² (для системы, где период Земли = 1 год при a = 1 а.е.)

## ЭТАП P1. Пульсар-часы: данные и расчёт

- В `packages/data`: скрипт загрузки параметров пульсаров. Источник — каталог ATNF (psrcat). Если программный доступ к каталогу сложен или недоступен — НЕ застревать: захардкодить таблицу из 6–8 пульсаров с параметрами из открытых источников (период P, производная периода Pdot, эпоха, координаты RA/Dec, расстояние). Обязательный набор: PSR B0531+21 (Краб), PSR B0833-45 (Vela), PSR B1919+21 (первый открытый), PSR B1937+21 (миллисекундный).
- В `packages/core/src/pulsar`: функция вычисления текущей фазы вращения пульсара на момент времени t по P, Pdot и эпохе. Честная модель: φ(t) = φ0 + (t−t0)/P − ½·Pdot·(t−t0)²/P².
- Тесты: фаза монотонна, период тика соответствует P, для Краба частота ~30 Гц.

Приёмка: тест выводит в консоль «Краб тикает N раз в секунду», N ≈ 30.

## ЭТАП P2. Пульсар-часы: интерфейс

- `apps/pulsar-clock`: визуальная пульсация в ритме выбранного пульсара (для миллисекундных — визуально показывать огибающую/стробоскопический эффект, не пытаться рисовать 600 кадров/с).
- Звук тика через Web Audio (для быстрых пульсаров — характерное жужжание: воспроизводить как тон с частотой вращения).
- Карточка пульсара: имя, период, расстояние, фраза «этот ритм шёл к Земле N лет» (N из расстояния в св. годах), координаты на небе.
- Переключатель пульсаров. Кнопка mute. Тёмная «космическая» тема.
- Дизайн: не дефолтный, аккуратный, минималистичный. Это витрина проекта.

Приёмка: пользователь открывает страницу, слышит тик Велы, переключает на Краба — слышит жужжание ~30 Гц, читает карточку.

## ЭТАП S1. Симулятор: физическое ядро

- `packages/core/src/nbody`: N-body гравитация. Интегратор — leapfrog (velocity Verlet). НЕ метод Эйлера.
- Состояние системы: массив тел {имя, масса, позиция, скорость}. Шаг интегрирования настраиваемый.
- ОБЯЗАТЕЛЬНЫЕ тесты:
  1. Двухтельная задача (Солнце + Земля): орбита замкнута, период = 1 год ± 0.1%.
  2. Сохранение полной энергии системы на 10 000 шагов: дрейф < 10⁻⁶ относительных.
  3. Сохранение момента импульса аналогично.
- `packages/data`: скрипт получения реальных положений/скоростей планет на текущую дату из NASA JPL Horizons API. Результат кэшируется в JSON в репозитории. Fallback: захардкоженный снимок Солнечной системы (Солнце, 8 планет, Луна, Плутон) на фиксированную дату из открытых эфемерид.

Приёмка: `npm test` зелёный, есть JSON с Солнечной системой.

## ЭТАП S2. Симулятор: визуализация

- `packages/render`: сцена Three.js — звёздный фон, тела как сферы (размер логарифмический от реального, иначе ничего не видно), следы орбит, орбит-контролы камеры.
- `apps/simulator`: загрузка Солнечной системы из JSON, управление временем (пауза, скорости от реального времени до миллионов лет/сек), клик по телу → карточка параметров (масса, скорость, эксцентриситет текущей орбиты).
- Панель диагностики: полная энергия системы, счётчик симулированного времени.

Приёмка: пользователь видит Солнечную систему, ускоряет время, планеты ходят по орбитам, энергия в панели стабильна.

## ЭТАП S3. Режим «сломай мир»

- Сценарии как JSON в `packages/data/scenarios/`: «без Юпитера», «вторая Луна», «пролёт блуждающей звезды», «Земля ×2 массы».
- UI: выбор сценария, удаление тела на лету, изменение массы слайдером, добавление нового тела кликом (позиция + начальная скорость).
- Индикация катастроф: тело покинуло систему (гиперболическая орбита) — подсветить и записать в журнал событий.

Приёмка: пользователь удаляет Юпитер и наблюдает за поясом астероидов... которого пока нет, поэтому минимум — наблюдает изменение орбит соседей; журнал фиксирует вылетевшие тела.

## ЭТАП S4. Headless-режим и агент-лаборант

- CLI-команда: прогнать сценарий без рендера N лет, выгрузить метрики (эксцентриситеты, большие полуоси, вылетевшие тела, дрейф энергии) в JSON/CSV.
- Документация в CLAUDE.md: как агенту запускать серии экспериментов и писать отчёты в markdown в папку `reports/`.
- Демонстрационный отчёт: «при какой массе Юпитера орбита Марса теряет стабильность» — серия прогонов, таблица, вывод.

Приёмка: в `reports/` лежит первый отчёт, сгенерированный по реальным прогонам.

## ЭТАП М. Склейка: дашборд

- `apps/dashboard`: единое приложение с двумя сценами на общем рендер-движке.
- Сцена «Система»: симулятор как в S2–S3.
- Сцена «Галактика»: при сильном отдалении камеры Солнечная система сжимается в точку, вокруг — пульсары из P1 на их реальных галактических координатах (пересчитать RA/Dec + расстояние в декартовы), каждый мигает в своём (замедленном для видимости) ритме. Клик по пульсару → его часы из P2.
- Плавный переход между масштабами.

Приёмка: пользователь отдаляется от Солнца, видит мигающие пульсары, кликает на Краба, попадает в часы.
