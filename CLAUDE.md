# Космический монорепозиторий

Два приложения на общем ядре: **пульсар-часы** и **орбитальный N-body симулятор**, в финале склеиваются в дашборд. Полная спецификация и этапы — в `SPACE_PROJECT_PLAN.md` (источник истины по порядку работ).

## Стек

TypeScript, Vite, Three.js, Web Audio API, Vitest. Монорепозиторий на npm workspaces. Node 18.

## Структура

```
packages/
  core/      # физика и астрономия: чистый TS, НОЛЬ зависимостей
    src/nbody/   # гравитация, интеграторы (leapfrog, не Эйлер)
    src/pulsar/  # расчёт фазы пульсаров
    src/units.ts # система единиц
    tests/
  render/    # общие Three.js-компоненты (сцена, звёзды, тела, следы орбит, DOM-подписи тел)
             # следы рисуются относительно самого массивного тела: в мировых
             # координатах при дрейфе системы они размазываются в «полосы»
  clock/     # переиспользуемый UI-компонент пульсар-часов (DOM + Web Audio)
  data/      # скрипты загрузки данных + закэшированные JSON
apps/
  pulsar-clock/  # часы на весь экран (порт 5183) — оболочка над @space/clock
  simulator/     # симулятор (порт 5184); экспортирует "simulator/app" для дашборда
  dashboard/     # обе сцены: система + галактика (порт 5185); экспортирует "dashboard/app"
  telegram/      # Telegram Mini App поверх дашборда (порт 5186, см. docs/telegram-miniapp.md)
  bot/           # бэкенд бота @pocket_cosmos_bot: Cloudflare Worker (webhook Telegram)
scripts/
  lab.ts     # headless-прогоны сценариев (npm run lab)
reports/     # отчёты агента-лаборанта + сырые данные прогонов
```

## Система единиц (packages/core/src/units.ts)

- Расстояние: а.е. Время: годы. Масса: массы Солнца.
- G = 4π² (период Земли = 1 год при a = 1 а.е.).
- Конвертация в км/с, секунды и т.п. — только на границах (UI, импорт данных).

npm run dev:pulsar     # пульсар-часы → http://localhost:5183

## Агент-лаборант: эксперименты и отчёты

`npm run lab` гоняет сценарий без рендера и выгружает метрики орбит
(большие полуоси, эксцентриситеты, вылетевшие тела, дрейф энергии).

```
npm run lab -- --scenario star-flyby --years 50                  # JSON в stdout
npm run lab -- --scenario base --years 500 --mass "Юпитер=10" \
  --out reports/data/run.json --csv reports/data/run.csv         # файлы
```

Флаги: `--scenario <id>` (base, no-jupiter, second-moon, star-flyby, earth-x2),
`--years`, `--dt` (по умолчанию 1e-3), `--sample` (интервал временного ряда),
`--mass "Имя=K"` и `--remove "Имя"` (повторяемые), `--out`, `--csv`.

Как писать отчёт по серии экспериментов:
1. Спланировать серию (какой параметр сканируем, какие критерии «поломки»).
2. Прогнать серию `npm run lab`, сырые JSON класть в `reports/data/`.
3. Отчёт — markdown в `reports/`: метод, команды воспроизведения, таблица
   результатов, выводы. Все цифры — только из реальных прогонов; контроль
   честности — дрейф энергии в каждом прогоне (должен быть ≪ 1e-4).
4. Пример: `reports/jupiter-mass-vs-mars.md`.

## Принципы

1. Малые итерации: один этап плана = один работающий, запускаемый результат. Этапы строго по порядку.
2. Физическое ядро (`packages/core`) обязательно покрыто тестами; тесты гонять после каждого изменения ядра. Никаких физических библиотек — гравитация и интеграторы пишутся руками.
3. Перед коммитом этапа: сборка без ошибок, тесты зелёные, dev-серверы поднимаются. Визуальные изменения проверять скриншотом через headless Chrome (команда — в `docs/telegram-miniapp.md`, раздел «Визуальная проверка»), а не только сборкой: сборка не ловит «работает, но выглядит сломанно».
4. Внешние API (ATNF psrcat, JPL Horizons) могут быть недоступны — использовать захардкоженные fallback-данные, не блокировать разработку.
5. КРИТИЧНО: `core` и `render` не зависят от Node.js API и специфики браузера сверх необходимого — впереди упаковка в Tauri и Capacitor. Платформенный код только в `apps/*`.
6. Код простой и читаемый, без преждевременных абстракций. Комментарии — на русском.
7. Пользователь не читает код: после каждого этапа давать ему короткую инструкцию «что запустить и что вы должны увидеть/услышать». Корректность — через автотесты, не через ревью пользователя.
